# アプリのログイン設定（毎回の入力を省く）

ログイン付きのMacan Controlは、**RenderのURLから開きます**。

- 今まで：`https://haniojp.github.io/macan-control/`
- ログイン付き：`https://macan-control-api.onrender.com/`

最初にアプリ用パスワードでログインします。「この端末でログイン状態を保持する」にチェックを入れておくと、30日間は再入力を省けます。Renderのスリープ・再起動後も、同じ設定なら保持されます。Porsche IDとパスワードはそのままで、アプリ内に接続キーを入力する必要はなくなります。

## 1. 今の履歴をバックアップする

URLが変わると、Safariの保存場所も変わります。履歴は自動移動できません。**設定前に、普段使っているSafariまたはホーム画面アプリで**次の2つを保存してください。

1. 現在のMacan Controlを開く。
2. **車両情報JSONバックアップ** を押して保存する。
3. メンテナンス記録の下にある **整備履歴JSONバックアップ** を押して保存する。

バックアップにPorscheのパスワード・接続キーは含まれません。保存ファイルを「ファイル」アプリで確認します。

## 2. GitHubの変更をマージする

今回のPull Requestを開き、**Merge pull request → Confirm merge** を押します。

この操作だけではログインは有効になりません。次にRenderで設定します。

## 3. Renderでアプリ用パスワードを設定する

1. **[Renderの管理画面](https://dashboard.render.com/)** を開く。
2. **macan-control-api** をクリックする。
3. 左メニューの **Environment** を押す。
4. **Edit** を押す。新しい項目を追加する **Add Environment Variable** で、以下の2行を追加する。

| KEY（項目名） | VALUE（値） |
| --- | --- |
| `APP_LOGIN_PASSWORD` | 自分で決めたアプリ用パスワード。12文字以上、英字・数字などを組み合わせる。Porscheのパスワードとは別にする |
| `APP_ORIGIN` | `https://macan-control-api.onrender.com`（末尾の / は付けない） |

5. **Save** を押す（Save, rebuild, and deployがあれば、それを選ぶ）。
6. 必要なら画面右上の **Manual Deploy → Deploy latest commit** を押す。
7. コミット番号の右側が緑の **✓ Live** になるまで待つ。

既存の `PORSCHE_EMAIL`、`PORSCHE_PASSWORD`、`BRIDGE_ACCESS_KEY`、`ALLOWED_ORIGIN` は変更しません。パスワードやキーはチャットに送る必要はありません。

実際のサービスURLが表と違う場合は、APP_ORIGINにRender画面に表示されたHTTPSのサービスURLを入力します。APP_ORIGINを省略した場合、Renderが提供するRENDER_EXTERNAL_URLを利用しますが、上のように明示する方が確認しやすくなります。

## 4. iPhoneでログインする

1. Safariで **https://macan-control-api.onrender.com/** を開く。
2. **アプリ用パスワード** に、手順3で決めた値を入力する。
3. 自分専用の端末なら **この端末でログイン状態を保持する（30日間）** にチェックを入れる。
4. **ログイン** を押す。ログイン後、車両情報は自動取得される。

表示されるのが「detail: Not Found」の場合は、Renderに今回のコードが反映されていないか、APP_LOGIN_PASSWORDが未設定です。手順3を確認してください。

## 5. 履歴を引き継ぐ

新しいログイン付きアプリで、手順1で保存したファイルを取り込みます。

1. **データ追加ボタン → JSONを取り込む** で、車両情報のJSONを選ぶ。
2. **メンテナンス記録 → バックアップJSON取込** で、整備履歴のJSONを選ぶ。
3. 履歴が移ったことを確認する。車両情報JSONは追加方式なので、同じファイルを繰り返し取り込まない。
4. **元のGitHub Pagesのアプリ** を開き、移行確認後に **メンテナンス記録** ボタンで専用画面を開いて、下部の **車両情報とメンテナンス記録をすべて削除** を押す。元の端末内データを残しておくと、その旧画面からはログインなしで以前の履歴を見られるため。バックアップと新アプリへの取込を確認するまでは削除しない。

今後は新しいRenderのURLを利用します。Safariの **共有 → ホーム画面に追加** で、新しい方のアイコンを作ってください。古いGitHub Pagesのアイコンと区別できるよう、追加時の名前を「Macan ログイン」などにできます。

## 普段の使い方

ホーム画面の新しいアイコンを開きます。30日の保持期間中は通常、ログイン画面を省いて表示します。

- **ログアウト**：画面の **ログアウト** を押す。次に開くとパスワード入力が必要。
- **期限切れ**：再度パスワードでログインする。
- **Renderの再起動**：通常は再ログイン不要。アプリ用パスワード・BRIDGE_ACCESS_KEYが変わった場合は再ログインする。
- **パスワードを忘れた**：RenderのEnvironmentでAPP_LOGIN_PASSWORDを新しく設定して再デプロイする。すべての端末で古いログインCookieが無効になる。
- **ブラウザのデータを削除した**：Cookieと履歴が消える場合がある。再ログイン・JSON復元が必要。
- **オフライン時**：ログイン付き画面はキャッシュしないため、通信できる状態で開く。無料サーバーの起動に時間がかかる場合がある。

## 技術的な仕様・限界

- アプリHTMLとAPIを同一オリジンにまとめ、Safariの第三者Cookie制限に依存しない。
- `__Host-`接頭辞付きSecure／HttpOnly／SameSite=Strictの署名Cookieを使用。認証情報をlocalStorageに書かず、JavaScriptからCookieを読めない。
- ログイン設定時は旧Bearer接続キーによる車両APIアクセスを拒否する。GitHub PagesにはRenderのログイン画面への案内だけを返す。
- 保持ありは固定30日、保持なしはセッションCookieかつサーバー側で最長12時間。端末のブラウザ復元機能によってセッションCookieが復元される場合がある。
- HMAC署名鍵を既存のランダムなBRIDGE_ACCESS_KEYとアプリ用パスワードのPBKDF2-SHA256派生値から用途を分けて導出。600,000回のパスワード導出、定数時間比較、5回失敗後の5分待機を実装。
- 署名Cookieはサーバー再起動後も検証可能。追加DB不要。ログアウトはそのブラウザのCookieを削除する方式で、盗まれたCookieを端末単位でサーバー失効させる仕組みはない。全セッションの失効はAPP_LOGIN_PASSWORDまたはBRIDGE_ACCESS_KEYの変更で行う。
- CSRF対策としてログイン・ログアウト・CAPTCHA送信のOriginを確認。CSP／frame-ancestors／no-storeを付加し、APIエラーでパスワード本文を返さない。
- 認証済みのページはService Workerでキャッシュしない。ログアウト後のBFCache復元はセッションを再確認する。
- 取得済み履歴は引き続きブラウザのlocalStorage内。履歴の暗号化や端末ロックの代替ではない。Safariとホーム画面アプリで保存領域が分かれる場合がある。
- 失敗回数の制限は1プロセスのメモリ内。既存のRender設定（1 worker）で使用する。パスワードを変更するまで全端末を個別管理する機能はない。
- アプリ用パスワードが未設定なら既存のBearer方式を維持し、今回のコードをマージするだけで既存の実車接続を止めない。設定後は必ずRenderのURLでログイン画面が出ることを確認する。
